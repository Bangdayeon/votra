### 3. 훅 임베드 시스템 (hookEvent / hookMatcher / hookScript)

**목표**: 스킬에 Claude Code 훅을 직접 임베드해서 기계적 강제 가능

**필드 의미**:
- `hookEvent`: `PreToolUse | PostToolUse | Stop | null`
- `hookMatcher`: Claude Code 툴 이름 (예: `"Edit"`, `"Bash"`, `"mcp__votra-memory__finish_task"`)
- `hookScript`: bash 스크립트 (exit 0 = 리마인더, exit 2 = 차단)

**Gemini 프롬프트**: 기계적으로 강제할 패턴이면 hook 필드 설정, 순수 맥락형이면 null

### 4. apply_hooks MCP 툴 + /api/memory/hooks 엔드포인트 (세션 2)

**배경**: 기존 SOP 스킬은 `brief` 텍스트로 주입 → 세션이 길어지면 컨텍스트 윈도우에서 밀려나 AI가 무시. 훅으로 기계적 강제가 필요하다는 방향으로 재설계.

**추가된 것**:

| 항목 | 내용 |
|------|------|
| DB migration `20260606000000_skill_hooks` | `ProjectCustomSkill`에 `hookEvent`, `hookMatcher`, `hookScript` 컬럼 추가 |
| `GET /api/memory/hooks` | 훅이 있는 활성 스킬만 반환. CLI `apply_hooks` 전용 |
| `geminiReflectionEngine` 프롬프트 개선 | 기계적 강제 가능 패턴 → hookEvent/hookMatcher/hookScript 생성. 맥락형 → null |
| `applySkillSuggestions.ts` | contextHint + 훅 필드 passthrough |
| `MemoryPageClient.tsx` UI | 훅 스킬 카드에 "훅 PreToolUse" amber 배지 + hookMatcher + hookScript 코드블록 + apply_hooks 안내 |
| `votra-cli apply_hooks` 툴 | `/api/memory/hooks` 조회 → `~/.votra/hooks/{slug}.sh` 생성 → `~/.claude/settings.json` PreToolUse/PostToolUse/Stop 훅 주입. 스테일 votra SOP 훅 자동 제거 |

**훅 작동 흐름**:
```
세션 완료 → log_session → 리플렉션 크론 → Gemini 패턴 3회+ 감지
→ ProjectCustomSkill에 hookScript 저장
→ Claude Code에서 apply_hooks 실행
→ ~/.votra/hooks/*.sh 생성 + ~/.claude/settings.json 등록
→ 이후 Edit/Bash 호출 전마다 SOP 리마인더 기계적 실행
```

**설계 결정**:
- 훅 없는 맥락형 스킬도 유지 (`hookEvent = null`) — 기존 brief 텍스트 주입 병존
- hookScript는 기본 exit 0 (리마인더), 명백한 오류 방지에만 exit 2 (차단)
- install.ts의 `suggest-skill.sh`, `auto-log-session` 훅은 stale 정리 대상에서 제외
